# 全国空气质量逐小时采集

从[中国环境监测总站实时发布平台](https://air.cnemc.cn:18007/)采集站点 AQI、PM₂.₅、PM₁₀、SO₂、NO₂、CO、O₃，按站点和年份保存，并记录站点名称、坐标变化。

程序仅使用 Python 3.12 标准库，无需安装第三方依赖。数据来自网站公开接口，接口当前未要求登录。接口地址、字段及可用时间范围可能发生变化。

## 定时运行

GitHub Actions 每天 **08:37、20:37 UTC** 执行，前后间隔均为 **12 小时**，对应北京时间 **16:37、次日04:37**。

```yaml
schedule:
  - cron: '37 8,20 * * *'
```

GitHub 没有公布足以确定“每日最低负载小时”的官方时间表。官方明确提醒整点负载高，建议选择其他分钟。因此本项目选择第37分钟以避开整点，并不承诺准点启动。[官方说明](https://docs.github.com/en/actions/how-tos/troubleshoot-workflows)

工作流还支持 **Actions → Collect AQI → Run workflow** 手动运行。修改采集代码、配置、测试或工作流并推送至 `main` 时，会自动进行测试和一次完整采集；普通数据更新不会再次触发采集。

工作流按顺序执行：离线测试 → 全量采集 → 提交成功取得的数据 → 上传本次报告。部分站点失败时，其余成功数据仍会保存，但整次工作流最终显示失败。数据推送失败也会明确报错。

## 数据格式与合并规则

每个站点每年一个 UTF-8、制表符分隔的 TXT 文件：`./yyyy/{StationCode}_yyyy.txt`。表头为：

```text
Time_UTC    AQI    PM2_5    PM10    SO2    NO2    CO    O3    Quality_flags
```

- 时间采用完整 UTC 时间，例如 `2026-10-23T16:00:00Z`；目录及文件年份也以**观测时间的 UTC 年份**划分。跨年窗口会分别写入两年文件。
- AQI 无量纲；CO 单位为 **mg/m³**；其余污染物为 **μg/m³**。
- 按站点及时间去重、排序。新有效数值逐字段覆盖旧值，即使数值下降也覆盖；新缺测不会覆盖已有有效数值。零是有效值。
- 缺测用 `NA` 表示；`Quality_flags` 是 JSON，保留主字段中无法作为非负有限数值解析的原始内容，包括空值和非数值说明。保留旧有效值时，其旧质量标记也保留；本次缺测统计见运行报告。
- 不把 `O3_8h`、`PM2_5_24h` 等扩展字段当作所需的逐小时六要素，不将分指数代替浓度。
- 同一份响应中编号错配、重复时间戳、未来异常时间会报错。默认最新观测超过6小时视为过期，不写入该站点响应。
- 返回不足24个小时，会保留实际可用小时并在报告中列出；不虚构补齐。24小时全部主字段缺测的站点也会单独列出。
- 文件写入采用临时文件、刷盘和原子替换，损坏的已有文件会报错而非静默覆盖。

主要接口：

```text
POST /HourChangesPublish/GetAllAQIPublishLive
POST /HourChangesPublish/GetAqiHistoryByCondition?stationCode=4166A
```

第一次读取站点列表；第二个接口每站一次返回最近24小时的七个主字段。本项目不使用日期快照接口拼接观测：实测旧日期查询可能回退至最新时刻，并且部分数值与逐站历史接口不一致。

## 站点改名与坐标变化

`StationCode` 是唯一键。`stations.csv` 的基础列为：

```text
StationCode,PositionName,Area,Longitude,Latitude,...,Sta_history
```

基础列永久保留该站点首次见到的值。当前名称和坐标在 `state.json` 的 `current` 中；通过**当前状态与上次状态比较**识别新事件，避免每天重复记录同一次变化。

名称变化在最后一列追加，多个事件用分号分隔：

```text
change name to 新站名 on 26.10.24; change name to 后续站名 on 27.03.02
```

经纬度任一变化时记录完整坐标对：

| 该站点变更次数 | 经度列 | 纬度列 | 时间列 |
|---|---|---|---|
| 第1次 | Lon_new1 | Lat_new1 | change_time |
| 第2次 | Lon_new2 | Lat_new2 | change_time2 |
| 后续 | 按序号扩展 | 按序号扩展 | 按序号扩展 |

整张表共享这些列，每个站点只填写自己已发生的变更；`Sta_history` 始终位于最后。数值相同但格式不同（如 `116.30` 和 `116.3000`）不会记为变化。

新增站点加入表格，并建立自己的首次基准。暂时消失的站点保留观测文件和历史，仅将 `state.json` 中 `present_in_latest_list` 标为 `false`。站点恢复时沿用其历史。`stations_initial.csv` 仍保留项目第一次运行的名单。

所有事件日期/时间为 **UTC 首次发现时间**，不是站点实际改名或迁址时间。两次采集之间发生后又恢复的变化无法检测。`Area` 首次值在表中保留、最新值在状态中保留，不单独扩展区域变更列。

## 请求、错误与停更检查

默认三个工作线程共享速率限制，所有请求（包括重试）的启动间隔至少0.5秒，即总体不超过每秒两次。超时20秒，最多三次尝试；对临时网络错误、429和部分5xx进行退避，对403等错误直接报错。不会关闭 TLS 证书验证。

单站失败后继续处理其他站点；最初20个完成请求均失败时停止，避免网站不可用时继续请求全国站点。站点总数比上次下降超过20%时停止元数据更新，防止错误响应把大量站点标为消失；确认来源确有变化后可手动加 `--allow-large-drop`。

远端采集失败时，会对源站 DNS 解析出的至多两个地址检查 TCP、TLS 和首页 HTTP 响应，并将结果保存为 `network_diagnostics.json`。它只检查源站18007端口，保持证书验证，不扫描其他主机或端口。诊断文件表示其 `checked_utc` 时刻的结果，成功运行不会将旧诊断改写为当前错误。

同一输出目录禁止同时运行两次。正常结束会清理 `.run.lock`；若程序被强制终止，只能在确认没有运行进程后手动删除残留锁。GitHub 工作流另外使用并发组串行执行。

`last_run.json` 包括采集起止时间、成功/失败站点、缺失小时、全缺测站点，以及新增、修订、补齐、保留旧有效值等数量。GitHub 工作流将最新结果复制为 `status.json` 提交到仓库，失败原因也可直接查看；此外每次报告保留为14天的 Artifact。详细日志不会持续提交到仓库。

GitHub 调度延迟、仓库 Actions 停用或网络访问限制都可能造成漏采。运行失败可在 Actions 页面查看；“完全没启动”的情况需要外部监控才可可靠告警，本项目尚未配置外部通知服务。超过24小时的漏采以及窗口之外的历史修订，目前无法保证补回。

## 年度归档

1. 最后一次更新该年度数据后，导入本地数据库，核对文件数、行数、时间范围和校验值，并保留备份。
2. 在 `config.json` 的 `archived_years` 中登记已完成归档的年份，例如 `[2026]`。建议与删除年度目录放在同一个提交中。
3. 确认本地归档后删除仓库中的对应年度目录。程序会跳过已归档年份，不会因24小时窗口跨年而重新创建旧年度文件。
4. 保留站点元数据三份文件，供下一年接续。

归档后该年度不再接收修订；需要恢复采集时，先恢复年度文件，再从 `archived_years` 中移除年份。

**删除工作树中的年度文件不会删除 Git 历史里的旧版本。** 如多年后需要实际减少仓库历史体积，应单独规划年度数据仓库或经过备份的历史清理；本程序不自动重写 Git 历史。

## GitHub 部署

将程序、配置、测试、元数据和数据推送至本仓库 `main` 分支。工作流使用仓库自带的 `GITHUB_TOKEN`，无需提供网站账号或单独配置个人令牌。仓库/组织策略必须允许工作流运行及 `contents: write`。

首次推送代码自动触发一次完整采集。以工作流实际成功和数据提交为准；本地运行成功不代表 GitHub Runner 的网络一定可访问该站点。后续定时任务运行在默认分支，因此请保持默认分支为 `main`。

执行环境由仓库变量 `AQI_RUNNER` 指定，未设置时采用 `ubuntu-latest`。选择了确实可以访问源站的自托管 Runner 后，可以将此变量设为该 Runner 的专用标签；目前尚未注册或启用任何自托管 Runner。也可在已确认的机器上直接定时运行本程序，再同步数据到仓库。[GitHub 自托管 Runner 说明](https://docs.github.com/en/actions/concepts/runners/self-hosted-runners)
